# Data provenance and interpretation

The package preserves selected numerical results from the project. A SHA-256
manifest identifies the release files. A checksum establishes file identity,
not accuracy or completeness of a mathematical computation.
Archived data files retain their original newline bytes through Git attributes
so their recorded checksums remain valid across platforms.

## Zeta computations

| File | Origin and interpretation |
| --- | --- |
| `data/eri_list.csv` | 10,142 original ERi evaluations at x=1.1, using the independent 460-digit Gram series; ordinates from Odlyzko's first-100,000 table |
| `data/pair_100k.npy` | Original fast-evaluator pair sums at x=1.1; array order follows the external first-100,000 ordinates |
| `data/pair_100k_x1.5.npy`, `pair_100k_x2.0.npy`, `pair_100k_x3.0.npy` | Archived three-point sweep pair arrays, each with 100,000 entries in the same order |
| `data/residues_60.csv` | Original zeta residues and derivative checks using mpmath zeta zeros |
| `data/residues_400.npy` | Archived 400-residue array; columns are ordinate, real residue and imaginary residue; the generator can reconstruct a separate array |
| `data/x_sweep.json` | Archived sweep summaries, with the historical field names retained |
| `data/figures/` | Figures generated by `compute/analyze.py` from the included Gram table and finite residue model |

Andrew Odlyzko's [source page](https://www-users.cse.umn.edu/~odlyzko/zeta_tables/)
describes the first 100,000 zeta ordinates as accurate within `3 × 10⁻⁹`.
The raw third-party table is not distributed here. The historical
`data/zeros1.txt` input has SHA-256:

```text
3436c916a7878261ac183fd7b9448c9a4736b8bbccf1356874a6ce1788541632
```

The `gamma` column of `eri_list.csv` retains these externally sourced
numerical coordinates to identify the computed values. They are credited to
Odlyzko and are outside the license grant for original ERi results.
The computed CSV columns and pair arrays are the project's numerical outputs.

At x=1.1 the first-60 normalized partial amplitude is approximately
`0.03910840860915`, and the first-400 value is `0.04171845843640`.
These are partial positive sums, not the infinite conditional envelope or
rigorous upper bounds for it. The archived sweep's `Rpred` field is likewise
a first-60 partial amplitude. Its historical `I` field contains fitted
transient estimates, now named `tau_estimates` by the current generator.
The last truncated octave must be interpreted as incomplete.

The sweep JSON is retained as an archive; it was not recomputed during release
packaging and can differ from the corrected generator's endpoint centering.
In particular, use the averaged prime count at x=2 and x=3 when interpreting
new results. Do not treat the archive as output from a new run of the current code.

The historical fast/Gram comparison found maximum absolute disagreement of
about `4.4 × 10⁻¹³`. Elliott's Ei convention was subsequently corrected in
both the Möbius head and tail. The constant shifts cancel in the entire ERi
sum, so the archived entire-function pair values are unchanged by that repair.

## Character-zero computations

| File or family | Origin and interpretation |
| --- | --- |
| `data/chi4_zeros_pari10000_clean.txt` | Canonical PARI/GP 2.17.4 list: precision 38, subdivision 32, height 10,000; 12,349 positive ordinates |
| `data/chi4_zeros_mp_snapshot.txt` | Independent archived mpmath sign-change scan; its header describes the intended larger run, while the retained snapshot ends earlier |
| `data/chi4_zeros_mp_6k8k.txt` | Independent mpmath scan covering the height-6,000-to-8,000 window |
| `data/chi4_zeros_to60.txt` | Small independently generated 25-zero mpmath list for smoke checks |
| `data/chi_D*_zeros_pari3000.txt` | Sixteen quadratic-character lists and numerical constants in comment headers, generated with PARI subdivision 16 |
| `data/chi5_c2_zeros_pari3000.txt`, `chi5_c3_zeros_pari3000.txt` | Separate conjugate order-four characters modulo 5: 3,237 and 3,236 positive ordinates |
| `data/eri_list_chi4.csv`, `eri_list_chi4.meta.json` | Full chi-minus-4 ERi pair cache at x=1.1, with source, evaluator, generator and CSV hashes |

The canonical chi-minus-4 input has SHA-256:

```text
80e9b8ca2cba6405bb3e0b33ca0e41bab8fb95d03964c0a0c7d9a468bc5f53d6
```

Recipes for the full archived PARI computations are in `compute/gp/`.
Project-generated lists are packaged instead of the downloaded LMFDB reference.
The initial count calibration was checked against 25 LMFDB zeros below 60;
the public checks use the included independent mpmath and PARI lists.
Sign-change scans, count heuristics and overlaps do not certify completeness.
Previously defective lists and their output tables are excluded.

## Tables

`data/paperB_q4.txt` is the current comparison of the chi-minus-4 sum with
the first-60 zeta-residue model. Its centre is fitted; its finite amplitudes
and incomplete final octave are explicitly labelled.

`data/theoremA_q4_pari10000_clean.txt` and
`data/theoremA_q4_eri_pari10000_clean.txt` retain the historical diagnostics
quoted in the real-character manuscript. Their header's comparison of
candidate constants records the earlier experiment. The printed `E(x,T)`
is the raw diagnostic, not Theorem A's remainder after the limiting constant
has been subtracted. At q=4 the correction is `κ = -log(2)`:
subtract `κ · Σ_{n≤N} μ(n)/n` from the raw `E` to obtain that remainder.
`E − m(N) B_T` uses the finite bracket and is another diagnostic.
The current `theoremA_q4.py` prints the corrected remainder and labels the
finite-bracket diagnostic separately. The historical `Etilde` column concerns
the alternative entire-ERi substitution, not the finite-cutoff identity.

`data/bracket_D_pari3000.txt`, `data/eri_series_chi5_pari3000.txt` and
`data/trivial_integrals.txt` retain the project's quadratic-character,
complex-character and trivial-integral experiments. For even characters,
the limiting bracket is `log L'(0,χ) − γ_E`; subtracting only `log L'(0,χ)`
leaves `−γ_E`.

Only the small staged generation and representative numerical checks are
rerun for this package. The full archived 10,000/100,000-zero searches remain
archived computations with the provenance above.
